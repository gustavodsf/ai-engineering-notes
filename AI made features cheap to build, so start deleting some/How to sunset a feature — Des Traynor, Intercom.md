# How to sunset a feature

Source: https://www.intercom.com/blog/how-to-sunset-a-feature  
Author: Des Traynor, Intercom  
Date: 23 April 2015 (older, but still the most cited practical playbook)  
Verified: HTTP 200, full text read on 27 November 2026. Companion post read too: "Before you plan your product roadmap" (2 Oct 2014, https://www.intercom.com/blog/before-you-plan-your-product-roadmap), which proposes the feature audit.

## Key points

- Leaving unloved features untouched, or parked at the bottom of the roadmap, is the same as keeping them. Unless you set out to build a bloated product, kill them.
- Step 1, confirm the condition is terminal: what % of eligible customers use it frequently, what % of revenue they represent, what was tried to raise usage, why non-adopters don't use it, and whether you would build it again.
- Step 2, stop offering it to new sign-ups: add a feature flag, remove it from the marketing site and sales talk.
- Step 3, split users into "real users" and "dabblers" (for example 1–5 events in a calendar, nothing in months). Hide it for dabblers.
- Step 4, announce end of life to the rest: what they used it for, a clear reason, alternatives, how to retrieve data, a firm date. Notice between a month and a year is typical.
- Companion audit post: plot each feature by how many people use it and how often. For a limited-adoption feature there are four choices: kill it, raise adoption, raise frequency, or deliberately improve it. Exclude admin features such as account creation and password reset.
